## 后续适配的具体落点

- 成长：`level.ts:131` 起的 XP 行为仍含产品/点子、双维度投票和模拟投资。保留历史 key/事件；新增帖子、反馈、社区作品等贡献规则另定义，不能只改中文名就把旧事件当新奖励。`profile/page.tsx` 已有等级卡和 `getOwnXpEvents`，不需另做一个成长系统。
- 后台：新内容审核、产品处理/合并、官方公告和活动公告各有不同权限。扩展原导航、队列及操作对象；`admin-guard.ts` 的页面/Action 双校验保留，不让普通用户因改前端分类就获得官方发布能力。
- 活动：原 `/activities` 的 `CheckinCard` 与 `LotteryWheel` 仍调用原服务端 RPC；`/community/activities` 目前是演示列表。需要把公告/详情和真实参与页连接，同时保持奖品库存、券余额与概率配置，不复制一套抽奖计算。

## 不直接复制的部分

- 原评论目标是 submission UUID，新演示帖是静态 slug。把演示 ID 填进真实 Action 会破坏内容归属，并可能触发通知/积分；必须先定义可持久化的内容及评论目标。
- 原 AI 专属审核、双维度付费/创意票、模拟投资不适用于新社区主路径。后台原功能存在，不代表新板块已经可管理。
- 活动和成长的前台文案必须与实际配置一致；本轮不改概率、奖励、等级阈值或数据库记录。
- 正式登录/旧产品接入已有其他批次记录，本盘点没有重做这些运行时验收，也不将它们扩大为新论坛发布成功。

先交付评论与独立发布页面供 review；再以 M2 内容模型承接真实论坛及回复；随后把新内容治理、贡献经验和活动公告接回原后台。每批必要 QA 和真实功能验收单独记录，不能以 UI 相似代替持久化验收。
