# 论坛反馈队列与审核并发独立 QA

日期：2026-11-04（Asia/Singapore）。论坛反馈候选 `879fdda`，管理员审核候选 `4055d6e`。

## 环境与结果

独立 QA 使用本机临时 PostgreSQL 16.9，通过私有 Unix socket 连接，不监听 TCP。原样执行 0001–0032（含 pgcrypto）及 0033；Supabase 的 auth/storage 平台表以本机测试桩代替，用户与业务数据均为虚构夹具。每轮使用四个独立数据库连接，通过 `pg_blocking_pids` 确认实际锁等待。11 组通过，未发现死锁、锁等待超时或新增上线阻塞。

1. 两个领取连接同时竞争，未提交事务期间只有一个有效租约。
2. 续期先于反馈编辑时，编辑等待源锁；提交后旧租约失效。
3. 反馈编辑先于续期时，续期等待源锁且不能复活旧版本。
4. 续期先于隐藏时，隐藏等待源锁；提交后旧租约失效。
5. 隐藏先于续期时，续期等待源锁且不能复活隐藏任务。
6. 租约在真实锁等待期间到期后，续期被拒绝。
7. 两个恢复连接保留已有任务关联，只轮换一次有效令牌。
8. 管理员列表先审核后，同一审核代次的相反队列操作被拒绝，经验和日志各一条。
9. 审核队列先处理后，同一审核代次的相反列表操作被拒绝，经验和日志各一条。
10. 同一代次并发创建审核队列时，只保留一条待审记录。
11. 续期先等待反馈源锁，不会先占用任务锁而阻塞编辑方，验证一致锁序。

首次测试脚手架尝试以普通账号直接锁反馈原表，收到预期的 ACL 拒绝 42501；未放宽权限，改用隔离库所有者仅构造阻塞后，该场景通过。连接设置 `statement_timeout=6s`、`lock_timeout=4s`，等待观测上限 2 秒。

本次未访问 Supabase、PostgREST、真实账号、正式数据库、项目环境凭证或浏览器；不是压力测试，也不等于正式迁移或线上验收。[机器结果摘要](forum-feedback-moderation-concurrency.results.json)保存在仓库；临时实例已停止，原始脚本和中间结果保存在本机临时测试目录 `/tmp/imtoken-postgres-qa.u2yKUu`。
