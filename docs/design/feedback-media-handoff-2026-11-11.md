# 产品反馈附件体验：设计交付

## 结论
- **方向（唯一）**：在现有反馈表单的正文字段下方加一个内联附件区，包含选择入口、敏感信息提示和文件列表。不新增页面、侧栏或导航入口，导航里的「发布」仍是唯一主要入口。
- **适用范围**：统一发布页中「产品反馈」分类的表单，以及论坛反馈表单，中英文版本都适用。
- **边界**：配额、格式、大小、处理时长和审核时效都由服务端返回，设计里不写死。文案通过变量引用这些值；如果服务端没有返回，就不显示对应文字。

## 1. 字段位置与页面结构

```
面包屑 / 页面标题（语义化 h1）
[分类：产品反馈]            ← 统一发布页已有
标题 *
正文 *
附件（可选）                ← 新增
  ├ 提示行：敏感信息警示（常驻，紧贴入口）
  ├ [＋ 添加图片或视频] 次级按钮 ＋ 限制说明（服务端值，可缺省）
  ├ 文件列表（0..n 行）
  └ 区域级状态/错误摘要（aria-live）
其余既有字段
[取消]  [提交] 主按钮
```

- **必需**：附件区在正文之后、提交按钮之前。敏感提示和选择按钮相邻显示，不另做卡片。
- **可调整**：桌面端支持拖放，拖放区就是附件区本身的虚线边框，不另建大块区域。
- **待决策**：附件在表单里是否允许为必填，由产品确认（默认可选）。

## 2. 视觉规格（沿用现有令牌）

| 项 | 规格 |
|---|---|
| 字段标签 | 与现有表单标签同级，「附件（可选）/ Attachments (optional)」 |
| 选择按钮 | 次级描边按钮，深蓝文字和边框，白底，高度 ≥44px；不用玫红，避免和「提交」争夺主要入口 |
| 敏感提示 | 小号正文，前置警示图标（带文字，不只靠颜色），深蓝文字；不使用大面积色块 |
| 文件行 | 白底，1px 浅灰分隔线，行高 ≥56px，内边距沿用表单间距令牌（建议 12/16px） |
| 进度条 | 深蓝填充，浅灰轨道，高 4px，并附百分比文字 |
| 错误 | 现有错误色，配图标和文字，对比度 ≥4.5:1 |
| 焦点 | 沿用全站焦点环，不能去掉 |

## 3. 文件行 / 列表

**桌面（≥ 断点）**：单列列表，每行结构如下：

```
[缩略图 48×48] 文件名（单行省略，title/全称可读）   状态文本   [操作]
               类型 · 大小 · 进度条(上传中)
```

**窄屏**：同样是单列，缩略图 40×40。文件名最多显示两行后截断，状态文本放到第二行，操作按钮在行尾保持 44×44 的触控区。页面不能横向溢出。

- **缩略图**：图片用本地预览；视频优先用本地首帧，取不到就用视频图标加时长（能取到时）。缩略图只来自本地预览，不加载服务端公开地址。
- **预览**：点击缩略图或「预览」打开现有模态（或系统原生播放器）。模态需要有焦点陷阱，按 Esc 关闭，关闭后焦点回到原触发按钮。视频不自动播放，默认静音控件可见。
- **排序**：按添加顺序排列，暂不支持拖动排序（待决策）。

## 4. 状态与文案意图

文案只表达意图，长度在中英文之间浮动；英文通常更长，布局需要允许换行。

| 状态 | 中文示意 | English | 可用操作 |
|---|---|---|---|
| 空 | 可添加图片或视频，帮助说明问题。 | Add images or videos to help explain the issue. | 添加 |
| 校验未通过（本地） | 该文件类型/大小不受支持：{原因} | This file can't be added: {reason} | 移除、重新选择 |
| 等待上传 | 等待上传 | Waiting to upload | 移除 |
| 上传中 | 正在上传 {n}% | Uploading {n}% | 取消 |
| 服务端处理中 | 已上传，正在处理 | Uploaded, processing | 移除 |
| 就绪 | 已附加，提交后进入审核 | Attached, will be reviewed after you submit | 预览、移除 |
| 失败 | 上传失败：{原因}。 | Upload failed: {reason}. | 重试、移除 |
| 断网 | 网络已断开，上传已暂停，未完成 | Offline. Upload paused, not complete | 恢复后重试、移除 |
| 无权限 / 会话失效 | 登录状态已变化，附件未上传，请重新登录后再试 | Your sign-in changed. Attachment wasn't uploaded. | 重新登录 |
| 提交后 | 附件待审核，仅授权人员可见 | Attachments pending review, visible to authorized staff only | 无 |

- **禁止**使用「已发布」「已公开」「上传成功」来描述审核前的状态。上传完成只能说「已附加/已上传，待审核」。
- 「{原因}」使用服务端或浏览器给出的可读原因，不要猜测原因。没有原因时显示通用文案：「请稍后重试」。
- **敏感提示（常驻）**：「请勿上传助记词、私钥、密码，或未遮挡的地址、余额、聊天等敏感信息。」/ "Don't upload recovery phrases, private keys, passwords, or unredacted sensitive info."
- **审核说明（就近，一行）**：「附件审核前仅授权人员可查看。」/ "Before review, only authorized staff can view attachments." 不写审核时效。

## 5. 提交期间与异常

- **有附件处于上传中或处理中**：提交按钮保持可用，点击后在区域摘要提示「仍有附件未完成上传」，焦点移到第一个未完成的行。该方案优先，也可以在提交按钮旁显示原因并禁用按钮（备选），二者由开发择一。
- **有附件失败**：提交时提示用户，并给两个选择：「移除失败附件后提交」或「返回处理」。不能静默丢弃失败附件。
- **提交中**：提交按钮显示加载态并防止重复点击。附件区的添加、移除、重试暂时禁用；禁用不只靠颜色，并通过 `aria-disabled` 和提示文字说明。
- **切换账户 / 会话失效**：清空未提交的上传状态，所有未完成的行标为未上传，不能沿用上一账户的成功状态。
- **关闭或刷新页面**：有未完成上传或未提交内容时，弹出浏览器原生离开确认。重新打开后，不恢复成「已上传」；是否保留草稿由产品决定（待决策）。
- **断网**：未完成的行标为暂停或未完成。恢复网络后由用户手动重试，不默认自动重试；是否自动重试待开发确认。
- **重新选择文件**：失败行提供「替换」，打开选择器后在原位置替换，旧上传取消。多选时新增行追加到末尾。

## 6. 焦点顺序与可访问性

1. 焦点顺序：正文 → 敏感提示（作为按钮的 `aria-describedby`，不单独占一个焦点）→「添加图片或视频」→ 每个文件行的操作，依次为预览、重试/替换、移除 → 后续字段 → 提交。
2. 文件选择使用原生 `<input type="file" multiple>`，外面包一层可见按钮，按 Enter 或 Space 触发。拖放只是附加方式，键盘路径必须完整。
3. 列表使用 `<ul>`，每行可访问名称包含「文件名 + 状态」。按钮名称要带上文件名，例如「移除 screenshot.png」/ "Remove screenshot.png"。
4. 区域级 `aria-live="polite"` 播报添加、完成、失败；失败用 `assertive` 播报一次。进度不逐个百分比播报，只在开始、完成和失败时播报，避免刷屏。进度条使用 `role="progressbar"` 并带数值。
5. 移除某行后，焦点移到下一行的同名按钮；没有下一行就移到上一行；列表为空时回到「添加」按钮。
6. 重试后焦点保持在该行，状态文本更新。
7. 状态不只靠颜色表达，每个状态都有图标和文字。动效遵循 `prefers-reduced-motion`。

## 7. 桌面 / 窄屏差异

| | 桌面 | 窄屏 |
|---|---|---|
| 选择 | 按钮 + 可拖放 | 按钮（系统相册/相机/文件选择） |
| 行布局 | 状态与文件名同行 | 状态换到第二行 |
| 预览 | 居中模态 | 全屏模态，顶部有关闭按钮 |
| 提交 | 维持现有表单底部 | 维持现有布局；不新增悬浮发帖按钮 |

## 8. 交接要点
- **必需**：唯一选择入口、常驻敏感提示、逐行状态与重试/移除、审核前不暗示公开、账户变化或断网时不显示成功、完整键盘和屏幕阅读器支持、中英文同步。
- **可调整**：缩略图尺寸、拖放视觉、未完成时提交的拦截方式、行内间距。
- **待决策**：
  - 配额、格式和大小限制（服务端提供）
  - 附件是否可以为必填
  - 草稿是否恢复
  - 是否自动重试
  - 是否支持排序
- **风险/未验证**：审核前的访问控制、上传取消与清理、视频首帧在各浏览器上的兼容性，都需要开发实现并由 QA 独立验证。本方案不代表这些后端能力已经具备。
