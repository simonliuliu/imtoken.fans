# imToken Fans 通用设计规则

更新：2026-10-16。适用于 Claude 设计交付、GPT 实现及页面 review。用户最新要求优先；历史设计稿与本规则冲突时，以本规则为准。

## 简洁与入口

- 内容优先，玫红、深蓝、白底；避免重复说明、装饰大卡片和无实际任务的模块。
- 同一页面同一操作只保留一个主要入口。论坛发帖统一放在导航栏；不再在板块标题、侧栏、“参与社区”卡片重复放发帖按钮。移动端也应只有一个可见入口。
- 板块位置由面包屑和导航表达，不再用“图标＋板块标题＋简介＋发帖”的大卡片重复介绍；保留语义化页面标题供辅助技术识别。
- 首页四板块入口由导航承担，不重复放入口网格。允许一个统一轮播位承载重点内容。
- 移除常驻“参与社区”和“安全提醒”卡片，列表中也不插入同样的提醒。敏感信息提示放在发帖、上传等相关操作处；安全指南作为内容按需访问。
- 侧栏只放当前任务有用且不重复的信息；没有必要内容就取消侧栏，不留空栏或用新卡片填满。已有独立功能入口按任务范围保留。

## 分类先于排序

- 四板块统一使用：面包屑 → 一级内容分类 → 当前分类下的排序／筛选 → 列表。
- 产品共创第一层为“全部／产品反馈／社区产品／产品公告”。钱包安全、综合交流、活动采用同样层级，各自使用适合本板块的分类。
- 推荐／最新／最热是当前分类内的排序或筛选，不是与产品反馈、社区产品等并列的功能模块。切换分类后保持排序选择，重置不适用的状态筛选和分页。
- 内容类型决定字段、互动和业务规则。反馈可有处理状态与支持，社区产品可有作品资料、支持和评价，公告突出发布来源与版本；不得为统一外观强行共用业务模型。
- 当前演示中最新按发布时间降序；最热按评论数、再按发布时间降序；推荐只取明确标记的内容。演示排序不代表正式业务规则已验收。后续不同模块的规则须由产品需求确认，不能擅自把点赞、支持或评分混合计热度。

## 交付前自检

- 桌面和移动端各检查一遍：有没有重复的发帖入口、板块介绍、导航或提醒？每个模块是否服务明确任务？
- 分类视觉层级是否高于排序？排序、状态和数量是否均限于当前分类？空分类、切换分类、切换排序是否正常？
- 中英文文案同步，窄屏分类可横向滚动但页面不横向溢出；保留键盘操作、焦点与可访问名称。
- 明确演示数据、局部互动与真实业务边界，不虚构官方回应、后端能力或活动承诺。
