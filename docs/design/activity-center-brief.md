# 活动中心设计 Brief

本次在现有 imToken Fans 钱包社区中实现用户活动中心。用户已同意实施，要求沿用当前 UIUX，并复用既有真实签到/九宫格抽奖，而不是再做一套。只给一个推荐方案和简洁规范（约1000字），不提供另一品牌方向，不生成工程代码。

既有风格：玫红 #e72b74 附近、深蓝 #192f54、白色面板/浅灰底，现有 header 与分类横栏、面包屑、列表保持不变。导航「活动」进入 `/community/activities`，不要新增并列活动导航。现有签到卡绿色/抽奖大紫色仅调整为论坛浅底/玫红强调，保留周期格子、进度和九宫格；旧 XP/券/中奖记录与配置都保持。

能力：真实活动列表/详情，类型有普通活动、新手任务、每周挑战；详情含标题、主办方/规则、开始结束时间、任务说明/奖励额度与参与动作。任务为签到自动核验、安全知识单选小测、产品体验/贡献提交后人工审核。另有我的参与（已参与、待审核、完成、被拒；奖励明细）、关注/取消关注、审核/到账/活动开始取消的站内消息。管理员使用既有后台管理活动，不在论坛增加重复发帖按钮。

建议一级分类：全部活动 / 新手任务 / 每周挑战 / 我的参与 / 签到抽奖；分类下状态过滤（进行中、即将开始、已结束/取消），分类视觉高于过滤。默认真实活动为空应诚实展示，不放虚拟活动、虚构人数、奖品或官方承诺。我的参与游客用统一登录引导；其他分类可公开浏览。页面保留语义H1但不要再加大标题介绍卡。单列为主，不放装饰侧栏/成长大卡。

详情：一处主参与按钮，必要的关注按钮为次操作；活动未开始、结束、取消、奖励耗尽、已提交待审、已完成均有明确状态。登录后回原活动。奖励按完成/审核通过规则发放，参加不锁定奖励名额；必须显示上限/规则，奖励不靠高分好评获得。没有奖励就明确写无额外奖励。敏感信息警示仅放贡献提交处，不收助记词、私钥、资产图。活动规则发布后冻结，取消要说明。

请交付：列表/详情/我的参与/签到抽奖四个视图结构，主要组件/状态与交互，桌面与390px手机行为，空/错误/加载/登录状态，中英排版及a11y。后台仅给最小配置字段与审核队列结构建议。不要假设新支付、钱包连接、报名名额、积分商城或离站通知能力。
