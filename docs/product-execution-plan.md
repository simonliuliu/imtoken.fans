版本：v3.1 · 更新：2026-10-16。M1-A2 演示与 M3-C Product Hunter 代码已汇入整合分支；UI 待用户 review，真实业务未验收，所有者授权规则已生效，PR #1–#4 已全部合入 main；正式站部署单独核验。

[详细产品需求](product-requirements.md)定义「做什么、规则和验收」；本文维护「已有基础、技术缺口和实施边界」；[路线图](../roadmap.md)维护任务状态。历史计划在 [归档](archive/imaihunt-product-execution-plan-v1.0.md)，不作为当前需求依据。

## 1. 当前定位与范围

imToken Fans 服务 imToken 钱包用户，四个一级板块为 **钱包安全、产品共创、综合交流、活动区**。

| 板块 | 首版内容与行为 | 需求依据 |
| --- | --- | --- |
| 钱包安全 | 官方/用户安全故事、案例、指南提醒、问答、评论与来源标识 | SAFE-01～04 |
| 产品共创 / 产品反馈 | 问题建议、搜索归类、图片与视频文件、单一支持、讨论、负责人/状态、人工合并及撤销、通知 | FB-01～07 |
| 产品共创 / 社区产品 | 用户自制产品展示、访问入口、创作者身份、支持和讨论；AI 为类别之一 | BUILD-01～04 |
| 产品共创 / 产品公告 | 授权官方公告/版本日志、来源、版本/平台筛选、关联反馈 | NEWS-01～04 |
| 综合交流 | 钱包经验、币圈行情与行业话题的基本论坛 | TALK-01 |
| 活动区 | 活动公告、列表详情、时间/规则、参与入口与已有签到抽奖 | EVENT-01～04 |

需求编号对应 [产品需求说明](product-requirements.md)。$BTC、PnL 和代币 agent 可后续做明确标注的假数据演示，不是已实现能力或首版发布必需项；真实行情、收益计算、交易与 agent 执行单独立项。模拟投资退出主路径，旧真实投资/NFT 计划继续暂停。

本轮改变：一级「产品反馈」改为「产品共创」；子区建议名「社区产品」以避免重名；不再将共创限定为 AI；人工合并从 M6 提前为 M3 首版必需。官方关系、承接人和响应时效仍需落实，不虚构承诺。

## 4. 数据与业务实现约束

优先比较扩展 submissions 与新建 posts 两种方案：前者减少评论/通知关系搬迁，后者便于拆出长文与作品字段，但要承担引用和兼容成本。M2-A 先给出选择依据、SQL 草案、全引用清单及回退，再实施；本轮不锁定表名。

必须分别表达：板块、内容类型、审核状态、反馈处理状态、可见性、作者/来源、媒体及归属、支持关系、负责人、版本关联、合并关系/操作事件。聚合查询不能混用模拟投资与支持票。

关键规则按 PRD 执行：

- 反馈首版为单人单条支持，可取消、重试幂等；合并去重到唯一参与者。需支持人工确认、旧链接追溯、原文/评论/附件保留、链式关系解析、撤销、并发与事务失败回滚，不能只加重复标签。
- 产品处理、反馈合并、公告发布、活动发布和抽奖管理独立授权；认证标签不代替权限。权限须覆盖真实服务端/数据库路径。
- 视频文件上传为 P1；媒体审核前访问、归属、删除恢复和孤立文件清理同批验证，公开桶不直接承载敏感未审附件。格式、大小/时长、预算在上传任务中落实，直传/续传方案需适配部署限制。
- 评论、通知、审核、成长和看板沿用基础但重审目标与语义；合并/迁移不重复发 XP，旧票和投资记录不改含义。
- 调整 AI 专属审核口径和 24 小时统一发帖冷却，适配四板块分类型限流；文本审核不能代表视频/图片已审核。
- 安全事件按最少收集原则，不收助记词、私钥、密码，不要求资产截图；公开故事与受控求助分开。PnL/agent 演示独立，禁止推断真实用户收益或伪装实时能力。

## 5. 品牌与体验约束

采用用户提供的 [Logo 参考](assets/imtoken-fans-logo-reference.png)，玫红强调操作、深蓝组织内容、白底确保阅读。沿用用户 review 后的内容列表方向；避免重复大段品牌介绍。四板块有统一导航，但详情、筛选与发布随内容类型变化，不能给公告、故事和活动套反馈处理状态。

产品共创内清楚区分「提问题/建议」「发自己做的产品」「看官方更新」。普通用户发帖菜单不提供官方公告入口。品牌与可信来源标识不能暗示社区作品获得官方背书。

全站定位、登录加入理由、说明页、规则/FAQ、metadata、图标/分享图及后台品牌入口仍需一致性清理。中英、手机/桌面、键盘焦点及减少动画偏好按阶段检查。

## 6. 实施与验收

| 阶段 | 交付 | 关键门槛 |
| --- | --- | --- |
| M1 | 演示 review 补充、新命名/三子区对齐、剩余品牌一致性 | 可预览结果交用户 review；文档完成不代替视觉通过 |

| M5 | 内容准备、回归、环境隔离与正式发布 | 四板块真实可用，生产关键路径、历史映射/旧 URL/回退通过 |
| M6 | 按真实需求增强及独立演示任务 | 自动去重候选/AI 分类、关注收藏/报名等；金融能力单独立项 |

优先级：P0 为定位/品牌/模型前置，P1 为四板块首版必需，P2 为运营增强和可选演示。具体任务和勾选状态只在路线图维护。

工程：应用变更跑 `npm run check-i18n`、`npm run lint`、`npm run build`；模型变更加类型、开发库读写和迁移演练。风险 QA 按 [工作流](agent-workflow.md)启用，权限/媒体/迁移/事务合并/重要跨模块流程必须独立检查。普通文档本轮由主调度自检，不启动设计或实现工作进程。

业务：游客/普通用户/运营/产品处理/公告发布等角色、中英桌面移动端、公开与未审内容、发布/支持/评论/合并/通知/公告/活动逐项验证。M5 前落实可信来源、官方关系措辞、反馈承接人与权限、首批作品/安全案例/真实公告/活动、域名/OAuth/钱包签名、媒体预算及生产凭证。

本轮需求整理已完成，后续应用调整尚未开始；M1-A2 仍待用户 review。下一步先依据 PRD 复核演示结构，再按阶段推进真实业务，不将本次需求说明当作实现验收。
