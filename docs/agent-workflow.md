更新：2026-10-15。**三条主线：总调度、Claude 设计、GPT 统一开发；QA 按风险启用。**
用户已于 2026-10-15 启动工程，当前响应 M1-A review，执行 M1-A2 社区浏览演示；每个重要阶段交可预览结果并等待 review。原九角色方案归档于 `docs/archive/agents-v1/`，不再注册为默认角色。

M1-A2 已完成可预览版本，见 [本批review](reviews/M1-A2-community.md)。Claude设计一次调用，GPT统一实现，本批没有命中必须独立安全QA的真实写入/权限/媒体变更。

设计及实现统一遵循 [通用设计规则](design/design-rules.md)。`run-claude-design.py` 每次调用自动读取并附入规则正文，缺失或为空时停止；不依赖 Claude 自行读取仓库。既有规范内的小修正直接由 GPT 实现，无需再次调用 Claude。

## 1. 当前角色

| 角色 | 模型/强度 | 实现方式 | 主要职责 |
| --- | --- | --- | --- |
| 总调度 | GPT-6.1 Sol / medium | 主聊天 | 理解需求、准备 Brief、分派、文件归属、整合、验收与进度 |
| 设计 designer | Claude Opus 5.5 / low | 现有 magpie → Devin 临时 CLI 工作进程 | 整体风格、信息架构、关键 UI/UX、设计交付 |
| 开发 developer | GPT-6.1 Sol / medium | 原生子 agent；小任务可覆盖为 Luna | 前端、后端、双语、数据库、媒体、实际实现与自检 |
| QA qa（按需） | GPT-6.1 Sol / high | 独立原生子 agent | 高风险变更的功能验证与安全审查 |

总调度不另建子聊天。文案、探索、小修复、前后端不再各常驻一个角色；主调度/开发按任务承担。前后端真的可独立时可启动两个 developer 实例，先统一接口并分配不重叠文件。

主配置注册 developer/qa；Claude designer 单独放在 `.codex/external-agents/designer.toml`，**不注册为原生子 agent**，防止原生角色继承 OpenAI provider 后错误调用。外部设计和原生开发都属于主调度的工作流程，但 CLI 进程不会作为当前 collaboration 原生子线程展示。

通常最多两个工作者并发，外部 Claude 也计入此预算；具体阶段先设计、后实现，不为了并发让开发猜设计。

## 2. 自动调用 Claude 的已验证渠道

用户确认使用 Codex 模型选择器里的 Cursor/Devin Claude。当前原生 `collaboration.spawn_agent` 只支持 OpenAI 模型，不能直接传 Claude ID。

实际测试：

- ChatGPT 默认 provider 请求 Cursor Claude：400，不支持该模型。
- 本机已配置的 magpie → Cursor：403，提供商地区限制拒绝。
- 本机已配置的 **magpie → Devin**，请求 `devin/claude-opus-5-5`：成功返回 `CLAUDE_ROUTE_OK`。

因此主调度可以通过 [调用脚本](../scripts/run-claude-design.py) 自动启动临时设计工作进程、读取输出并交给 GPT 实现。使用既有用户配置，**不安装凭证、不修改全局 provider、权限或网络**。渠道内部的模型路由与实际账单仍由提供商决定；连接回执不是独立验证底层模型身份。

这里调用的是 Claude Opus 5.5 设计角色，不等于调用 Anthropic Claude Design 工作台或其画布。若将来需要工作台原型，需要另行使用该产品并交接产物。

示例：

```bash
python3 scripts/run-claude-design.py \
  --brief docs/design/M1-brief.md \
  --output docs/design/M1-design-v1.md \
  --image docs/assets/imtoken-fans-logo-reference.png
```

`M1-brief.md` 在用户启动任务后由主调度创建；当前只提供 [Brief 模板](design/brief-template.md)。验证参数、不调用 Claude：加 `--dry-run`。

脚本要求 Python 3.11+、本机 Codex CLI 及已配置的 magpie/Devin 渠道。它读取设计角色 Prompt 和明确的 Brief，可附最多三张参考图；使用隔离临时工作目录、read-only、ephemeral，关闭工具/技能等可关闭上下文来源。一次运行一次调用，不自动重试、不切模型。输出是 Markdown 设计交付和 `.run.json` 请求/用量记录；拒绝覆盖已有产物。

失败时报告渠道原因并停下该设计调用，开发/主调度可以继续不依赖设计的工作。不能静默改用 Cursor 或 GPT 重新设计；更换设计渠道/模型应由用户意图和当前验证决定。

## 3. 节省 Claude Token

1. GPT 先盘点、整理用户需求和真实功能，形成短 Brief；不把全库或整段聊天传给 Claude。
2. Claude 先做代表页面和共用设计规范；首轮最多两个方向，选定后集中修订一次。
3. 交付页面结构、颜色/字体/间距、组件与状态、移动端行为，明确必需与可调整项。
4. GPT 按规范实现与微调；只有重大方向/交互改变才回 Claude，不让其参与日常修 bug、读构建日志或重复整页生成。
5. 脚本限制 Brief 最多 18,000 字符、参考图最多三张；这些是输入规模限制，不是硬 Token/金额预算。
6. 记录实际用量。CLI 有固定上下文开销；短回答也不等于低输入消耗。服务端/网关重试与账单不能仅靠本地参数证明为零，实际费用以提供商记录为准。

默认低推理用于设计探索与规范整理；困难任务需要时显式评估更高强度，不自动常驻最高档。不可承诺固定节省比例。

## 4. QA 何时启用

| 改动 | 谁检查 | 独立 QA |
| --- | --- | --- |
| 文案、颜色、间距、简单静态布局 | developer 自检；相关 i18n/预览 | 不默认启动 |
| 常规页面/组件调整、明确的小修复 | developer 按实际影响检查相关交互、移动端/双语，必需 lint/build 等 | 按实际复杂度或用户要求 |
| 登录/会话、钱包签名、权限/RLS、API 授权 | developer 实现并验证，qa 独立检查越权/失败路径 | 必须 |
| 上传、文件归属/访问、未审核媒体、敏感信息 | developer 验证，qa 检查公开性与滥用边界 | 必须 |
| 迁移/历史数据、事务/唯一约束、抽奖库存/次数/并发、重要跨模块流程 | developer 演练，qa 做独立回归/完整性检查 | 必须 |
| 阶段发布或用户明确要求 | 根据阶段范围安排验收 | 按阶段风险与验收计划 |

QA 合并功能验证与安全审查，不再另外常驻 reviewer。普通变更不因使用多 agent 而增加一套审查；必要工程检查仍执行，不等于免验收。QA 只审本批实际风险，发现确认问题后由开发修复，复测受影响范围。没有测试环境就标未验证，不宣称全面安全。

## 5. 标准流程

1. **总调度定义任务**：读 AGENTS.md、roadmap、最新用户指令与代码；填 [任务卡](tasks/template.md)，列风险和是否需要 QA。
2. **设计（有设计需求时）**：主调度整理 Brief，调用 Claude，保存交付；用户已授权实施的阶段，可先按推荐方向完成可评审首稿；用户明确要求先审设计时先交设计。既有规范下的小改动直接开发。
3. **统一开发**：GPT developer 负责前后端；小任务用 Luna 覆盖，复杂/高风险实现按需 Sol/high。前后端并行先定接口和文件归属。
4. **按风险检查**：普通变更由开发自检；风险矩阵命中时独立 qa 审查。必需整合检查集中执行，不并行 build、迁移或活动写入。
5. **主调度交付**：核验设计、实现和检查证据，更新任务卡与路线图，报告限制；重要样式/功能阶段等待用户 review 后再进入下一阶段。

同一方向经一次针对性重试仍失败、任务越界或接口冲突，携证据回主调度，不盲目重复调用 Claude。

## 6. 文件归属与运行配置

- 两份 messages、全局 CSS、公共类型、锁文件、迁移一次一个写入者；主调度指定 developer 归属。
- Claude 默认不读仓库、不使用工具、不改代码；由主调度提供约束并保存设计交付。图片通过 `--image` 仅在需要时提供。
- 任务卡、路线图与整体决策由主调度维护。并行开发不能相互覆盖。
- 原生 developer/qa：读取对应 `.codex/agents/*.toml`；当前通用 spawn 显式传模型与强度及角色指令，用独立上下文并补齐工作目录/约束。本次覆盖不要被命名角色固定值覆盖。
- QA 只能只读或用任务明确的开发环境验证；写库、账号、活动测试不触碰未明确的生产环境。
- Prompt 只读与文件归属不是独立沙箱；原生 agent 继承主会话权限。Claude CLI 工作进程额外使用 read-only，不扩权。
- 不创建/消息额外用户聊天、不修改个人全局配置、不自动提交整个仓库。当前项目无提交，worktree 前需建立合适基线。

## 7. 后续怎么指挥

开始设计：

> 按三角色工作流开始 M1，先让 Claude Opus 5.5 经 Devin 给首页与四板块导航做设计。先给两个方向，暂不开发，控制上下文和轮次。

设计确定后实现：

> 按选定的设计交付，让 developer 完成前后端实现。普通页面调整由开发自检，涉及权限/上传/迁移时启动独立 QA。

小改动：

> 调整这处文案/间距，交开发用 Luna 完成并做必要检查，不启动 Claude 或独立 QA。

安全改动：

> 修改钱包登录/上传权限，开发用 Sol/high，完成后必须让 QA 独立检查安全和回归。

状态/暂停：

> 汇报各角色、文件归属、设计与验证结果，继续当前批次。
>
> 停止本批工作进程与子 agent，保留文件并汇报进度。

上述为指挥示例；当前真实进度以 roadmap 和本批任务卡为准。
