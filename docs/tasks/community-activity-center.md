开始：2026-10-16 · 更新：2026-10-17 · 分支：`codex/community-activity-center` · 初始基线：`4e1f417`，已同步主线至 `9cd7be7` · 状态：实现与本地验证完成，待 PR / 用户 review；未激活线上活动。

## 目标与已授权边界

用户要求在顶部「活动」入口建设促活中心，复用现有 `/activities` 的真实签到、券制抽奖、账号/成长/通知和后台，沿用当前论坛 UIUX，在新分支实现并交 review。

本批包括：真实活动列表/详情/时间状态；新手与每周任务（安全小测、签到核验、产品体验反馈及人工贡献审核）；我的参与/审核/奖励记录；活动关注与站内通知；管理员草稿/发布/取消、审核及奖励额度管理。仅复用现有奖励资产，不新增商城、裂变、排行、支付/钱包授权、限额抢报名或邮件/短信推送。

现有签到/抽奖配置（含可选扣经验）和历史记录一律不重置。原 `/activities` 兼容到社区活动中的签到抽奖分类；同步最新主线后保留已有活动交流帖子、旧 slug/UUID 详情及真实评论、赞同、通知。示例正文保持标识，不能凭示例内容自动完成活动任务。新活动初始为空，未配置不发布、不发真实券，不能用演示内容冒充真实活动。用户未要求自动合并或线上运营启用。

## 实现约束与风险

- 社区唯一账号/会话；游客浏览，参与使用统一登录和带语言的回跳；切换账号清除旧个人状态/未提交证据。Server Action 比较 expectedUserId 与服务端实际用户。
- 任务必须服务端核验；体验反馈/手工贡献先提交审核，不因点赞/打开链接/高评分直接发奖。
- 已发布活动的任务/奖励/时间规则冻结；只能按说明取消，已发奖励不自动追回。后台只用已有 manage_campaigns 权限，不把身份标签当权限。
- 新增迁移，不改历史迁移/旧余额与记录；奖励事务锁定活动、单人单活动唯一，XP/券/徽章/参与状态/发奖记录一起提交，额度耗尽不超发。
- 复用现有通知入口。审核/到账为事务通知；关注后活动开始/取消为可取消订阅通知。站内轮询送达，不承诺离站 push。清空通知不能重播奖励或历史消息。
- 新建结构先在隔离 PostgreSQL 测试；共享 Supabase 已承载正式站，本批不在其执行试验或自动迁移。缺迁移明确报配置状态，不退回假数据或假成功。
- 前台中英成对；后台中文；北京时间划日/活动规则；手机、键盘、加载/空/错误/权限状态完整。文案/迁移/公共类型唯一写入者。

## 分工与验收

主调度：同步分支、任务/Brief、整合、独立验证与 PR。设计：按仓库既有 Claude 渠道一次精简交付，不重做品牌。开发：统一前后端/迁移/双语。QA：独立只读审查权限、RLS、账户竞态、奖励幂等/额度、历史兼容。

验收包括：公开与草稿可见性、非法/跨账号动作、过期/取消/重复提交、错误答案与次数、人工审核、奖励/通知去重、余额及旧记录不变、手机/双语、旧 URL/登录回跳；i18n、lint、build、隔离 SQL 与浏览器回归。实际执行与限制在交付时补充，不把源码/模拟测试称为线上验收。

## 2026-10-17 review 与修复

独立 QA 确认三项 P2，均已修复：

1. `product_ratings.created_at` 原可被 authenticated 修改，导致活动时间核验不可信。新增数据库触发器：普通客户端新评价由服务端赋时，既有评价的 ID、归属和创建时间不可改；正文/评分及原 Action 的 upsert 继续可用，不回填或改写旧评价时间。

## 环境、上线顺序与回退

隔离数据库脚本 `scripts/tests/activity-center-database.mjs` 不读取 `.env.local`，不连接 Supabase；仅模拟平台 auth/storage schema 和角色，应用 SQL 为实际迁移。可通过 `FEEDBACK_QA_PGLITE` 指向仓库外安装的 PGlite 模块复跑。单连接验证顺序事务、重复请求、跨用户总额度及故障回滚，不宣称已完成真实多连接并发压测。

共享 Supabase 与线上未执行本批迁移或活动写入。发布前确认 0001–0031 已完成，执行 0032，再部署相应代码；由有 `manage_campaigns` 权限的账号在 `/admin/campaigns` 创建草稿并 review 后发布。迁移不种运营活动、不改签到/抽奖配置和余额。
