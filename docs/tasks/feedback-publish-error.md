## 原因及交付

- 原错误提示在长弹窗顶部，移动端实际测得提示位于视口上方（top -85px），提交按钮位于底部，失败原因不可见。
- 本地缺少 Supabase 公共连接配置。已将正式页面公开的客户端 URL/anon 配置写入被 Git 忽略的 `.env.local`，只在本机使用；未复制服务端密钥。只读反馈 RPC 返回 HTTP 200。
- 错误提示与「登录后继续」入口移至提交按钮上方，失败后自动聚焦、滚动显示，保留填写内容；按钮关联提示。重复失败也会重新聚焦。
- UUID 生成纳入异常处理，空错误与异常结果显示兜底提示；同步阻止重复提交，重试沿用请求 ID；保留账户切换及卸载后的响应隔离。相似搜索异常不会成为未捕获拒绝。
- PR #13 已合并，本批从最新 `origin/main`（de69d6c）新建 `codex/jack-feedback-publish-error`，不修改主线。

用户确认实际提交失败是尚未登录论坛；本地配置准备属于独立环境问题，不能把它当作这次匿名提交被拒绝的业务根因。

- 未登录在按钮前显示中性说明，按钮为「登录后继续发布」；允许空表单直接登录，也可先写内容并保留草稿。匿名不会调用发布 Action；服务端会话失效仍由原认证校验拦截，转相同登录入口。登录返回产品反馈并恢复草稿，跨账号隔离规则不变。
